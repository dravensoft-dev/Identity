# scripts/lib/arena/

What belongs to no one layer: the parsers, the browser harness, and the tree's own facts.

| module | why it exists |
| --- | --- |
| `repo-root.ts` | The repository root, derived once. Every script imports it from here rather than counting `..` from its own location, so a script's depth under `scripts/` is not part of what it has to get right. **The one place that counts**, which is why moving this file needs care. |
| `arena-scripts-vars.ts` | Every environment variable the scripts read, declared once so a test run or a CI run needs no exports. `arenaEnv()` lays the declared values under the real environment, which wins, so a one-off override stays a shell prefix rather than an edit to a versioned file. `skipExitCode()` is the single reading of `ARENA_CHECK_STRICT` and `CI` that all four skippable gates share. |
| `layers.ts` | `LAYERS` and the two name shapes every gate reads a layer through. An **exhaustive enumeration**, deliberately not a walk of `frameworks/`, so a layer renamed or removed wholesale becomes loud instead of quietly leaving scope. `kebab()` derives a directory name from a PascalCase one: a function, never a table. |
| `comments.ts` | Lexes source, so a `//` inside a string, a regex or a template literal is never mistaken for a comment, and a `@ts-`/`eslint-` directive is a directive rather than the file's one allowance. `literalRanges()` reports where the literals are so a second reader can ask whether a match sits inside one: that is what tells an import a generator WRITES from one it performs. It reports ranges rather than erasing them, because a specifier is itself a string, and erasing strings would erase the very thing the resolver reads and leave the scan silently reporting nothing. Kept dependency-free so it runs under plain node. |
| `markdown-prose.ts` | Splits a Markdown document into its prose runs, one per line, so the punctuation rule never judges the code a document quotes. Both skips are lexed: a fence closes only on a run of its own character at least as long as the one that opened it, and a code span only on a backtick run of exactly its own length, which may be lines below. Kept dependency-free so it runs under plain node. |
| `css-decls.ts` | Parses a stylesheet into selector → declaration maps. Read by the token drift gate and by the Overview page, so both judge the same text the same way. It reaches a browser through `build:intro`, which bundles the page that imports it; before that step existed it had to stay JavaScript. |
| `api-surface.ts` | Reads a layer's declared API surface out of source text, by regex. A shape it cannot read **throws** rather than going silently missing from the member list, because a member absent by accident and a member absent by design look identical downstream. |
| `behaviour-contracts.ts` | Loads and validates the behaviour patterns and each layer's bindings. `bindingCases()` is the **single** place the flat and cased binding shapes are reconciled. |
| `playground-model.ts` | Derives a component's playground from its API contract and its `frameworks/demos/` fixture: which knobs exist, what each starts holding, whether it starts bound, and how it round-trips through a URL. Pure and layer-neutral, and the **single** place any of that is decided, so the two layers cannot disagree about a control. A form it cannot model throws, because a member missing by accident and a member missing by design look identical on a page. |
| `playground-page.ts` | The demo page every layer serves, built in one place so the two differ in exactly the two lines they have to: what mounts the app, and what the app is loaded from. A page authored per layer would drift in its stylesheet list or its toggle markup, and a difference in the frame reads as a difference in the component. A cross-layer emitter is outside what `check:layer-independence` scopes, being the mechanism that keeps the layers comparable rather than an instance of the coupling. `sheetLinks()` is that stylesheet list: the preflight plus one sheet per surface the page draws, resolved through `manifestFor()` so a compound child links its parent's. |
| `composed-surfaces.ts` | Which components a component renders INSIDE itself, read from every layer's source and **unioned**. A fixture says what a page instantiates and cannot say this, and the answer differs by layer while the page must not: React's `ArenaUnauthCard` composes `ArenaCard` and Angular's draws the same frame from its own manifest. Read from the import graph rather than from a render, so a branch no knob has taken yet still gets its stylesheet. `check:playgrounds` is what holds the result: it fails a page rendering an `arena-*__*` class no sheet it links defines. |
| `chromium.ts` | Finds and launches a headless browser from `CHROME_PATH` or the usual paths. Returns nothing rather than throwing when there is none, so each gate that needs one decides for itself what the absence costs. **`CHROME_PATH` is terminal, not a preference**: set and pointing at nothing, it reports that rather than falling back to the candidate list, because a path someone wrote down and a path that happens to exist are different claims. |
| `domains.ts` | The five phase domains every script sorts itself into, declared once so a gate and its runner cannot disagree about which job runs it. It also declares the extension lists and the `isScript`/`isSuite` pair that says what counts as either, because **four separate scanners walk this tree** -- `check-all.ts`'s `testFilesUnder()`, `summarize-tests.ts`'s `suiteDomains()` and `script-imports.test.ts`'s `scriptsUnder()` -- and a suffix one of them stops recognising does not fail: the file quietly leaves that scanner's scope and keeps every gate green. `domainOfTestPath()` classifies by directory rather than by suffix, so it needed nothing for the migration and is stated here as the reason it needed nothing. Since the migration finished the two lists differ and the difference is the point: **`SUITE_EXTENSIONS` is `.ts` alone**, because nothing loads a suite and so no suite can earn an exception, and **`SCRIPT_EXTENSIONS` still holds `.mjs`**, because `STAYS_JAVASCRIPT` names four modules that remain JavaScript for reasons this repository cannot change, and a scan proving specifiers must still reach them. That map is asserted **exhaustively in both directions**: a fifth `.mjs` fails as an exception nobody argued for, and an entry whose file has been renamed fails as a stale one. |
| `cdp.ts` | The Chrome DevTools Protocol dispatcher the viewport gate drives the browser with. |
| `package-assembly.ts` | What both npm package builds share: the exclusion list deciding what never ships, the copy that honours it, the CSS chain each package carries, and the manifest template that stamps the version from `plugin.json`. `arena` because it reads two framework layers and the repository root. It compiles nothing; each layer's builder does that with its own toolchain. |
| `component-map.ts` | What a consumer writes and the component sheet it costs, derived per layer and carried in each package as `components.json`, so `arena-to-prod` can resolve `"components": "auto"` without guessing. The link is **derived, never conventional**: 43 sheets dress 55 components, and a row, an item and a tab wear their parent's, so it is read off the manifest each component's styles import. It also closes what Arena draws for the consumer, since a table renders a pagination and a select and a subset missing them is a silent unstyled render. **Each layer gets its own map because they differ in fact**: React's confirm dialog renders an `ArenaButton` and Angular's draws its own out of its own manifest. |
| `contract-shapes.ts` | The shape `contracts/api/` holds on disk, so the scripts that read those files agree about it. Every one of them reaches a contract's members through `Object.entries()` over a `JSON.parse`, which hands back `unknown`, and a gate that then reads `.form` off an entry is making a claim about the file it never states. `memberEntries()` and `fieldEntries()` are that claim, in one place, and the first two consumers are `check:api` and `check:playgrounds`. It describes the **source** contract and never the API a consumer sees: `Api.generated.ts` is emitted from these files and is a different document for a different reader. The keys are derived from the contracts themselves, with one exception stated in the file: `MEMBER_FORMS` is read from `contracts/api/MemberForms.md`, because `consumerData` is a legal form no component uses today and deriving the eight from the instances would silently drop it. `check:api` reads the list from here rather than repeating it. |
| `typecheck.ts` | Spawning tsc over a tsconfig, for the two gates that do it: `check:react-types` over the React layer and `check:script-types` over the tooling itself. A library rather than a function hanging off either gate, because a gate importing another domain's gate would make the domain grid a lie, and `lib/` is the one direction always allowed. `arena` by the vocabulary rule: tsc and tsconfig belong to no single layer. `check:angular` keeps its own runner, sharing the shape and none of the code, because `ngc` emits into a temporary tree rather than checking in place. `projectFiles()` is here so a gate can prove its project matched something: a tsconfig whose globs match nothing compiles nothing and reports clean, which is the one way a typecheck gate passes over a tree it never opened. |
| `static-server.ts` | The static file server behind `bun run demos`, and the fixture the card gate loads pages from. Its own suite asserts a real `fetch`, which is why the DOM-free test invocation must stay DOM-free. |

Every `X.test.mjs` beside a module covers that module.
